# Arabic Sprint (Vocabulary Speedrunner)

Arabic Sprint أداة تدريب على مفردات اللغة العربية بأسلوب السباق السريع (speedrun)، وتعمل داخل Docker. تعرض الشاشة المعنى بالصينية، ويكتب المستخدم الكلمة بالعربية. وتجمع الأداة بين اختيار الكلمات الجديدة اعتمادًا على تكرار الكلمات في ويكيبيديا، والتدريب المكثّف قصير المدى، والمراجعة طويلة المدى وفق خوارزمية FSRS-4.5، وتستخدم نموذج Ollama محليًا أو سحابيًا للحكم على الإجابات التي لا تطابق الإجابة القياسية تمامًا.

## الميزات وتخطيط الصفحة

- **السؤال بالصينية والإجابة بالعربية**: يعتمد حقل الإدخال والإجابة تخطيط الكتابة من اليمين إلى اليسار (RTL).
- **قائمة نماذج Ollama**: يبقى `gemma4:cloud` ضمن القائمة، إلى جانب النماذج التي نُزّلت على خدمة Ollama المتصلة حاليًا. تُحدَّث قائمة النماذج تقريبًا كل 15 ثانية.
- **جدولة FSRS-4.5**: تُجدول المراجعة طويلة المدى بحسب صعوبة الكلمة في الذاكرة، وثباتها، ونتيجة الإجابة، والوقت المنقضي منذ آخر مراجعة.
- **التدريب المكثّف قصير المدى (speedrun)**: تعود الكلمات المصنّفة Again بأولوية بعد الإجابة عن ثلاثة أسئلة أخرى؛ وإذا لم تتوفر أسئلة أخرى يمكن الإجابة عنها، يُعاد التدريب عليها مبكرًا.
- **التقييم بحسب السرعة**: تُصنَّف الإجابات الصحيحة إلى Easy أو Good أو Hard وفق متوسط زمن إجابة المستخدم نفسه وانحرافه المعياري.
- **حفظ البيانات في SQLite**: تُحفظ فيها تقدّم كل كلمة، وحالة FSRS، وزمن الإجابة عن كل تصحيح معتمد.
- **النشر عبر Docker Compose**: توضع قاعدة SQLite في وحدة تخزين (volume) مسمّاة، وتوفّر الحاوية نقطة فحص صحة هي `/healthz`.

بعد بدء الاختبار تنقسم الصفحة على سطح المكتب إلى ثلاثة أعمدة. يعرض العمود الأيسر في أعلاه متوسط زمن الإجابة والانحراف المعياري، وأسفله مخططًا دائريًا لآخر تقييم FSRS لكل كلمة سبقت الإجابة عنها. ويعرض العمود الأوسط في أعلاه نسبة الكلمات المجاب عنها إلى غير المجاب عنها في بنك الأسئلة، وتتوسطه بطاقة الإجابة. ويعرض العمود الأيمن عدد طلبات Ollama Cloud واستهلاك الرموز (tokens) في هذا الاختبار. وفي الشاشات الضيقة يتحول التخطيط إلى عمود واحد. وتبقى المخططات الإحصائية ظاهرة عند انتهاء الاختبار.

يعتمد المتوسط والانحراف المعياري على العيّنات الصالحة في التقييم بحسب السرعة، ولا يشملان التدريب قصير المدى بعد Again؛ أما المخطط الدائري لـ FSRS فيعدّ **آخر تقييم** لكل كلمة سبقت الإجابة عنها، فتُحسب كل كلمة مرة واحدة فقط.

> لا يحصي جدول الاستهلاك إلا الطلبات والرموز التي أبلغ عنها `gemma4:cloud` في اختبار الواجهة الحالي، ولا يمثّل خطة حسابك في Ollama ولا إجمالي استهلاك الحساب ولا الحصة المتبقية. تُقارَن الإجابات المطابقة تمامًا محليًا دون استدعاء النموذج. وعند استخدام Cloud للحكم على الإجابة، تُرسل إلى Ollama Cloud للمعالجة كلٌّ من الجملة الصينية للسؤال، والكلمة العربية القياسية، وإجابة المستخدم.

## التشغيل لأول مرة

### 1. تجهيز Ollama

ثبّت Ollama وشغّله على الجهاز الذي يشغّل Docker. لاستخدام نموذج سحابي، سجّل الدخول إلى Ollama أولًا؛ ولاستخدام نموذج محلي، نزّل النموذج أولًا، مثلًا:

```bash
ollama signin
ollama pull gemma4:e4b
```

النموذج الافتراضي هو `gemma4:cloud`. ويمكنك من أعلى يمين صفحة الاختبار التبديل إلى أي نموذج محلي نُزّل في خدمة Ollama. وتتصل حاوية Docker بتلك الخدمة عبر `OLLAMA_API_ENDPOINT`.

### 2. تشغيل Docker Compose

نفّذ الأمر التالي في مجلد المشروع:

```bash
docker compose up -d --build
```

افتح <http://localhost:5000> في المتصفح، ثم اضغط «بدء الاختبار» لاستخدام بنك الأسئلة المرفق بالمشروع. لعرض مخرجات الحاوية:

```bash
docker compose logs -f
```

لإيقاف الخدمة:

```bash
docker compose down
```

إذا عدّلت الشيفرة أو الأنماط أو الصفحات أو ملفات CSV، فأعد البناء والتشغيل:

```bash
docker compose up -d --build
```

يعتمد هذا المشروع Docker وسيلةً للاستخدام والنشر. ولا تتضمن صورة Docker نماذج Ollama ولا خدمة Ollama نفسها.

## بنك الأسئلة وبيانات تكرار الكلمات

لا تحتاج في الاستخدام الأول إلى تنزيل أي مدوّنة لغوية ولا إلى تنفيذ أي تنظيف للبيانات. تتضمن صورة Docker ما يلي:

- `exam_list.csv`: 234 كلمة تدريب افتراضية.
- `voc_database.csv`: بيانات مرتّبة مسبقًا لتكرار الكلمات العربية، وتبلغ حاليًا نحو 2,552 مدخلًا.

لتخصيص بنك الأسئلة، عدّل الملف `exam_list.csv` في جذر المشروع، بترميز UTF-8 مع الإبقاء على الأعمدة التالية، ثم أعد بناء الحاوية:

```csv
arabic_word,translation
كتاب,書本
سيارة,汽車
بيت,房子
```

عند اختيار الكلمات الجديدة، يحسب البرنامج أوزان النسب المئوية باستخدام الكلمات **التي لها بيانات تكرار** فقط في بنك الأسئلة، ضمن النطاق من `0.5` إلى `1.5`. ولا تُعامَل الكلمات غير الموجودة في بيانات التكرار على أنها الأقل تكرارًا، بل تأخذ الوزن المتوسط `1.0`، وتشير الصفحة إليها بعبارة «التكرار غير معروف». وبعد أن تبدأ الإجابة عن كلمة ما، تتولى FSRS جدولة مراجعتها اللاحقة، ولا يغيّر تكرار الكلمة فترات FSRS.

## التصحيح والمراجعة

### الحكم على الإجابة

1. إذا طابقت الإجابة الإجابة القياسية تمامًا، حُكم بصحتها مباشرة دون استدعاء النموذج.
2. إذا اختلفت الإجابة، يتجاهل البرنامج علامات التشكيل العربية ويحسب عدد الحروف العربية المشتركة بين الإجابتين؛ وتُحسب الحروف المكررة بحسب عدد مرات ظهورها. وإذا اشتركت الإجابتان في ثلاثة حروف على الأقل، يحكم النموذج أولًا هل هي صيغة مفرد/جمع للكلمة نفسها. وإذا تأكد ذلك عُدّت الإجابة صحيحة.
3. تُصنَّف سائر الإجابات بواسطة النموذج بحسب قرب المعنى: الإجابة القريبة المعنى التي لا تطابق الإجابة القياسية تأخذ `Hard (2)`؛ والإجابة غير ذات الصلة أو الخاطئة تأخذ `Again (1)`. ولا تُعدّ المرادفات أو الكلمات ذات الصلة صحيحة تلقائيًا.

### تقييم Easy وGood وHard بحسب السرعة

يُسجَّل زمن الإجابة بالثواني لكل سؤال، من لحظة ظهوره حتى إرسال الإجابة. ولا تُصنَّف بحسب سرعة المستخدم إلا الإجابات الصحيحة:

- أقل من متوسط زمن الإجابة بانحراف معياري واحد أو أكثر: `Easy (4)`.
- ضمن نطاق المتوسط زائد أو ناقص انحراف معياري واحد: `Good (3)`.
- أكثر من متوسط زمن الإجابة بانحراف معياري واحد أو أكثر: `Hard (2)`.

يستخدم المتوسط والانحراف المعياري للعيّنة أزمنة الإجابة الصالحة السابقة للمستخدم؛ ولا يُفعَّل التصنيف بحسب السرعة إلا بوجود قيمتين على الأقل. وعند قلة البيانات تُسجَّل الإجابة الصحيحة Good. ولا تُلغي السرعةُ حكمَ Hard الدلالي الذي يصدره النموذج. ويواصل التدريب قصير المدى تسجيل الزمن، لكنه لا يدخل في خط الأساس للسرعة، ولا يُحكم عليه بـ Easy لمجرد أن الإجابة رُئيت قبل قليل.

### التدريب قصير المدى وFSRS-4.5

تدخل الكلمات المصنّفة Again في صفّ تدريب قصير المدى محفوظ، وتعود بأولوية بعد إكمال ثلاثة أسئلة أخرى؛ وإذا أُخطئ فيها مرة أخرى أُعيدت إلى الصف. وإذا لم تتوفر أسئلة أخرى يمكن الإجابة عنها، أُعيد التدريب مبكرًا لئلا يتعطل بنك الأسئلة الصغير. وبعد الإجابة الصحيحة في التدريب قصير المدى تخرج الكلمة من الصف، ثم تُراجَع بفترات FSRS طويلة المدى. وما زال الحد الأدنى لفترة جدولة FSRS الرئيسية يومًا كاملًا؛ أما صفّ التدريب قصير المدى فهو مسار إضافي يستخدمه السباق السريع.

تتبع الجدولة طويلة المدى [خوارزمية FSRS-4.5](https://github.com/open-spaced-repetition/fsrs4anki/wiki/The-Algorithm/bc401d9ed5093c66358738f4b8834f8d24ab211b) بالإصدار المحدد، وتحسب صعوبة الذاكرة `D` والثبات `S` وإمكانية الاسترجاع `R`. ويستخدم البرنامج أوزان FSRS-4 الافتراضية المدرجة في تلك الصفحة ومنحنى النسيان الخاص بـ FSRS-4.5:

```text
R(t,S) = (1 + 19/81 × t/S)^(-0.5)
```

تقييمات FSRS هي `Again (1)` و`Hard (2)` و`Good (3)` و`Easy (4)`. وتقدّم الجدولة أولًا التدريب قصير المدى المستحق، ثم مراجعات FSRS المستحقة؛ ولا تُسحب كلمات جديدة إلا إذا لم تكن هناك بطاقات مستحقة. وتُختار المراجعات المستحقة بحسب إمكانية الاسترجاع المتوقعة من الأدنى إلى الأعلى. وتُحسب الفترات بالأيام وتُقرَّب إلى أيام كاملة، بحد أدنى افتراضي يوم واحد وحد أقصى 36,500 يوم، دون إضافة تشويش عشوائي إلى الفترات.

يؤدي «إيقاف الاختبار مؤقتًا» أثناء الاختبار إلى تجميد مؤقّت السؤال الحالي؛ وعند الاستئناف يستمر الحساب من الزمن المتراكم قبل الإيقاف. ولا يُحتسب ضمن زمن الإجابة الوقتُ الذي يقضيه النموذج في التصحيح.

## حفظ البيانات وإعادة الضبط

يحصل كل متصفح عند أول استخدام على معرّف تعلّم مجهول، يُحفظ في ملف تعريف ارتباط (Cookie) موقَّع؛ وتبلغ صلاحيته سنة واحدة افتراضيًا. وتؤدي المتصفحات المختلفة، أو مسح ملفات تعريف الارتباط، إلى إنشاء ملف تعلّم جديد؛ ولا توجد حسابات ولا مزامنة بين الأجهزة.

تحفظ SQLite ما يلي:

- لكل كلمة: عدد الإجابات الصحيحة/الخاطئة، وآخر وقت إجابة، وصعوبة FSRS وثباتها، وموعد الاستحقاق التالي، والتقييم الحالي.
- لكل تصحيح معتمد: التقييم، وزمن الإجابة بالثواني، وهل استُخدم في الإحصاءات الزمنية.
- تقدّم التدريب قصير المدى لكلمات Again.

يضع Docker Compose قاعدة البيانات في وحدة التخزين المسمّاة `quiz_progress_data`. ولا يحذف الأمر `docker compose down` بيانات التعلّم؛ **لا تنفّذ `docker compose down -v` إلا إذا أردت حذف تلك الوحدة وجميع سجلات التعلّم**. ويحذف زر «مسح سجلات التعلّم» في الصفحة التقدّم وسجلّ أزمنة الإجابة المرتبطين بمعرّف المتصفح الحالي. وقد استُبعدت ملفات SQLite والملفات المؤقتة من Git ومن سياق بناء Docker.

إعداد SQLite مناسب لجهاز واحد ونسخة تطبيق واحدة. وتُضاف الأعمدة اللازمة تلقائيًا إلى قواعد البيانات الموجودة عند بدء التطبيق؛ ولأن السجلات القديمة لا تحتوي على أزمنة إجابة، لا يمكن استرجاع خط الأساس القديم للسرعة. وإذا أُزيل ملف تعريف الارتباط، تبقى بيانات المعرّف القديم في وحدة التخزين، لكن الصفحة لا تستطيع استرجاع ذلك المعرّف تلقائيًا.

## الإعدادات

يقرأ Compose ملف `.env` في جذر المشروع. وفي التطوير المحلي المعتاد يمكنك عدم إنشاء `.env` واستخدام الإعدادات الافتراضية للتطوير الموجودة في `compose.yaml`. أما في بيئات النشر فانسخ القالب:

```bash
cp .env.example .env
```

يستخدم القالب `APP_ENV=production`؛ ويجب قبل التشغيل ضبط `FLASK_SECRET_KEY` بما لا يقل عن 32 حرفًا، وضبط `OLLAMA_API_ENDPOINT` على عنوان `/api/chat` الخاص بـ Ollama والذي تستطيع الحاوية الاتصال به. ولا تستخدم `host.docker.internal` في إعدادات النشر السحابي.

| المتغيّر | القيمة الافتراضية | الوصف |
|---|---|---|
| `OLLAMA_MODEL` | `gemma4:cloud` | نموذج التصحيح الافتراضي؛ ويمكن تبديل النموذج من الصفحة. |
| `OLLAMA_API_ENDPOINT` | `http://host.docker.internal:11434/api/chat` | عنوان واجهة Ollama البرمجية الذي تتصل به الحاوية. |
| `OLLAMA_CONNECT_TIMEOUT_SECONDS` | `10` | عدد ثوانٍ الانتظار عند إنشاء الاتصال بـ Ollama. |
| `OLLAMA_READ_TIMEOUT_SECONDS` | `600` | عدد ثوانٍ الانتظار لاستجابة النموذج؛ ارفعه للنماذج البطيئة. |
| `OLLAMA_KEEP_ALIVE` | `30m` | المدة التي تُبقي فيها Ollama النموذج المحمَّل في الذاكرة. |
| `FSRS_DESIRED_RETENTION` | `0.9` | معدل الاحتفاظ المستهدف في FSRS؛ يجب أن يكون أكبر من 0 وأقل من 1. |
| `FSRS_MAXIMUM_INTERVAL_DAYS` | `36500` | الحد الأقصى (بالأيام) لفترة المراجعة طويلة المدى في FSRS. |
| `DATABASE_PATH` | `/data/quiz_progress.sqlite3` (في Compose) | موقع قاعدة بيانات SQLite لسجلات التعلّم. |
| `SESSION_LIFETIME_DAYS` | `365` | عدد أيام صلاحية ملف تعريف الارتباط لمعرّف التعلّم المجهول. |
| `APP_ENV` | `development` (في Compose) | يُضبط على `production` في بيئات الإنتاج. |
| `FLASK_SECRET_KEY` | فارغ | مطلوب في الإنتاج؛ 32 حرفًا على الأقل. |

لتوليد مفتاح سري باستخدام Docker:

```bash
docker run --rm python:3.12-slim python -c "import secrets; print(secrets.token_hex(32))"
```

بعد تعديل `.env` أعد بناء الحاوية:

```bash
docker compose up -d --build
```

## الأسئلة الشائعة

- **تعذّر اتصال الصفحة بـ Ollama**: تأكد من أن Ollama يعمل، وأن `OLLAMA_API_ENDPOINT` عنوان يمكن الوصول إليه من داخل الحاوية. ولا يمكن استخدام `host.docker.internal` في النشر السحابي.
- **انتهت مهلة استجابة النموذج**: مدة الانتظار الافتراضية 600 ثانية، ويمكنك رفع `OLLAMA_READ_TIMEOUT_SECONDS` في `.env` ثم إعادة بناء الحاوية.
- **لا تعرض قائمة النماذج النماذج المحلية**: تأتي القائمة من نقطة `/api/tags` في الخدمة التي يشير إليها `OLLAMA_API_ENDPOINT`. تأكد أولًا من أن مضيف Ollama قد نزّل نماذج، وانتظر نحو 15 ثانية كحد أقصى حتى تتحدّث ذاكرة التخزين المؤقت للقائمة.
- **ظهور أخطاء عند إعادة البناء بـ `docker-compose` القديم**: يُنصح بتثبيت Docker Compose v2 واستخدام الأمر `docker compose`.
- **التحقق من حالة خدمة الويب**: نفّذ `docker compose ps`؛ ومسار فحص صحة الحاوية هو `/healthz`. ولعرض الأخطاء التفصيلية استخدم `docker compose logs -f`.
